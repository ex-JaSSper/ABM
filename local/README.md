# Локальная разработка (SQLite)

Локальная песочница, чтобы тестить изменения **не трогая боевой Supabase**. Тот же `web/index.html`, но данные пишутся в локальную SQLite.

## Быстрый старт

```bash
# 1. создать/пересоздать локальную базу (схема + стартовая стратегия + KPI)
node local/init-db.mjs --reset

# 2. запустить локальный сервер (SQLite + REST + отдача web/)
node local/server.mjs
```

Открыть **http://localhost:8787** — приложение работает на локальной базе. Прод-Supabase при этом не затрагивается.

## Как это устроено

- **`schema.sqlite.sql`** — схема БД (зеркало прод-Supabase), адаптированная под SQLite: `TEXT` для id (UUID), `INTEGER 0/1` для булевых, `REAL` для чисел, `TEXT` (ISO) для дат, `CHECK`-энумы, внешние ключи, индексы.
- **`init-db.mjs`** — создаёт `local/abm.db` из схемы и засевает одну чистую стратегию + 5 KPI. Флаг `--reset` удаляет старую базу.
- **`server.mjs`** — дев-сервер (node:http + node:sqlite) на порту `8787`:
  - отдаёт статику из `web/`;
  - обслуживает `/rest/v1/<table>` в подмножестве PostgREST (GET `select=*`, POST upsert по PK, DELETE по `id=in.(…)` / фильтрам, PATCH) — ровно то, что использует `supabase-js` в приложении;
  - разрешает CORS.
- **`web/index.html`** сам определяет режим: если открыт с `localhost`/`127.0.0.1` **или** с `?local` в адресе → пишет в локальный сервер; иначе — в боевой Supabase.

## Требования
- Node 22+ (используется встроенный `node:sqlite`). Проверено на Node 24. Внешних зависимостей нет.

## Заметки
- Файл `local/abm.db` в git не коммитится (см. `.gitignore`) — это локальные тестовые данные.
- Схема должна оставаться в синхроне с `supabase/db-setup.sql`. При изменении модели правим оба файла.

## Полная замена данных в Supabase

Подготовленный набор стратегии, гипотез, задач, компаний и контактов лежит в
`supabase/seed-digital-efficiency-2026-08.json`. Перед заменой скрипт сохраняет
текущие таблицы в `local/backups/` и при ошибке пытается автоматически вернуть их.

```bash
node local/replace-data.mjs --remote --confirm-replace
```
